# API Spec

Hand-written companion to the generated spec. `docs/swagger.yaml` (generated by `swaggo/swag` from handler annotations, served at `/swagger/index.html`) is the source of truth — this file is kept in sync with it, but the generated spec wins on any conflict.

## Required (graded against assignment spec)

### `GET /mock-his/patient/search/{id}` — mock Hospital A HIS
Standalone, simulates the external system. Not called by the middleware at request time. Mounted under `/mock-his` (rather than task 1's literal `/patient/search/{id}`) to avoid colliding with the middleware's own `GET /patient/search` route on the same router.
- **Params**: `id` (string) — `national_id` or `passport_id`
- **200**: patient fields per assignment (bilingual names, DOB, HN, ids, phone, email, gender)
- **404**: no match in the hardcoded fixture set

### `POST /staff/create`
- **Auth**: required (JWT of an existing staff)
- **Body**: `{ username, password, hospital }` — `hospital` is a code string looked up against `Hospital.code`
- **Rule**: `hospital` must equal the caller's own hospital — otherwise `403`
- **201**: created staff (no password/hash in response)
- **400**: unknown hospital code, username already taken in that hospital, validation errors
- **401**: missing/invalid/expired token
- **403**: hospital mismatch

### `POST /staff/login`
- **Body**: `{ username, password, hospital }`
- **200**: `{ access_token, refresh_token }`
- **401**: bad credentials or hospital mismatch (generic message, no user-enumeration hint)

### `GET /patient/search`
- **Auth**: required
- **Query params** (all optional): `national_id`, `passport_id`, `first_name`, `middle_name`, `last_name`, `date_of_birth`, `phone_number`, `email`, `limit`, `offset`
- **Matching**: AND across provided filter fields; exact match on identifiers/DOB/phone/email; `ILIKE` partial match on name fields (checked against both `_th` and `_en` columns)
- **Scope**: results restricted to `hospital_id` derived from the caller's JWT, never from client input
- **Pagination**: `limit` defaults to 20, capped at 100 regardless of what's requested (prevents a single query from dumping an entire hospital's patient table); `offset` defaults to 0. `limit=0` is a valid, deliberate request — returns zero rows but the real `total`, useful for "just tell me the count." Results are ordered by `created_at, id` for stable, non-overlapping pages.
- **200**: `{ patients: [...], total, limit, offset }` — `total` is the full match count across all pages, not just this page's row count
- **400**: invalid `date_of_birth`, or `limit`/`offset` not a non-negative integer
- **401**: missing/invalid/expired token

## Bonus (beyond stated spec — documented separately so core requirement satisfaction stays unambiguous)

### `POST /staff/refresh`
- **Body**: `{ refresh_token }`
- **200**: new `{ access_token, refresh_token }`; old refresh token is deleted (rotation, no reuse-detection)
- **401**: refresh token invalid, expired, or already rotated/revoked

### `POST /staff/logout`
- **Auth**: required
- **Body**: `{ refresh_token }`
- **204**: refresh token deleted
- **401**: missing/invalid access token

## Error shape

```json
{ "error": "human-readable message" }
```

Consistent across all endpoints; HTTP status code carries the category (400 validation, 401 auth, 403 tenant mismatch, 404 not found, 500 unexpected).
